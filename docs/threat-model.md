# Threat model · native Windows assistant source 0.4.0

Assets: device/project integrity, accounts, provider credentials, user-selected targets, search context and downloaded/selected executables. Use an ordinary Windows account. The app is not an OS sandbox and does not claim that a confirmation dialog can make arbitrary code harmless.

| Threat | Current boundary / residual risk |
|---|---|
| Model/prompt injection | AI produces one strict typed action or local follow-up intent. Duplicate/extra fields, arbitrary code, ungrounded URLs and local selection handles are rejected. AI cannot approve. Page/file content is not sent unless present in the user's explicit request; no general browser/file agent exists. A valid search/navigation can still be wrong; inspect exact preview. |
| Beyond a hardcoded app list | A user-requested local Start-menu scan yields names/AppIDs and expiring handles. Names never enter PowerShell. Package IDs are cross-checked against local package manifests. Classic shortcuts are not launched because they may contain hidden args; user selects an actual `.exe`. It is fingerprinted/rechecked, invoked with no arguments and its directory as cwd. No signature/publisher verification; any launched program can use the user's permissions. Registration/executable replacement racing the final launch is not fully prevented. |
| Installation/download | Current `install X` searches Google for official Windows download results only. Explicit HTTPS navigation is allowed after exact preview. No WinGet/install command, auto-download, downloaded-code launch, publisher verification or silent UAC. Browser sites/redirects may trigger their own downloads. |
| Project mistakes | User selects one project root and exact file. UTF-8 text ≤256 KiB; exact unique string; path traversal, reparse/symlink, hardlinks and stale file identities/hashes are rejected. A reviewed diff exports to a new `.patch` outside the project through a single-use broker action and a second native confirmation. Existing source is never modified/applied/deleted. Path checks are not a race-free Windows sandbox; a hostile concurrent process can race them. Patch tools do not bind the preamble hash/root, so manually verify before applying. |
| URL or argument injection | Search text is encoded; HTTPS navigation rejects credentials/control chars/non-HTTPS. AI destination must exactly occur in the approved request. Process launches use argument arrays, `shell=False`, and no model-supplied args. Redirected sites remain untrusted. |
| Spotify side effect | Default search/liked-song actions use the registered Spotify URI handler; explicit browser choice uses HTTPS. URI behavior varies by installed client and is unverified on Windows here. Search opens results only; no track is auto-selected/played. |
| Unauthorized web request / DNS rebinding | Native startup has no listener. Optional local web mode retains bearer token, exact loopback Host, same-Origin mutation, JSON-only route validation, no CORS and independent native consent. Remote control/reverse proxy is unsupported. |
| Approval replay/race | Immutable broker action, one-use opaque ID, two-minute expiry, serialized execution. App/file selection handles expire and are separate from approval. Patch target/hash and file state are bound to reviewed output and checked again at export. Pause/cancel/request edits revoke pending work. A committed OS launch cannot be recalled. |
| Native approval | Cancel owns focus; Enter/Escape deny; Allow is a deliberate click after review delay. Dialog validity is polled. OS malware can synthesize input or alter local code. |
| Provider secrets/data | Cloud API requests disclose provider/model/current prompt. Keys masked, not in prompt/activity; HTTPS, no redirects/proxies/retry/fallback; session-only app memory. Explicit AI disclosure is required. Providers may retain prompts; don't send secrets or code unless you deliberately accept that exposure. No credential vault. |
| Logging | Bounded session activity labels/status only, no prompt/search/path/file contents. Browser/provider/Windows may keep independent history or telemetry. Exported patches contain code snippets, selected project path and base hash; store privately. |
| Denial of service | Input/output and provider timeouts bounded; one AI request, one action, bounded activity; app scan timeout and per-file limits. PowerShell inventory can still be slow. No sustained-DoS guarantees. |

## Tests and known gaps

Tests exercise strict model schemas, URL grounding, app inventory validation/selection, executable hash drift, exact patch replacement, duplicate/missing text, file identity changes, links/hardlinks, patch formatting, central broker approval/replay, plus mocked Windows dispatch. The current Linux environment cannot validate a real Windows desktop, Start-menu/AppX API behavior, protocol handlers, Tk appearance/hotkeys or EXE packaging. Seven Tk/display tests skip. No provider call was made.

Not implemented: automatic package installation or downloads, direct file edit/delete, browser DOM/accessibility automation, multi-step autonomous executor, voice, OAuth, plugin sandbox, signed build or remote pairing. User-selected executables are arbitrary code chosen by the user and can still be malicious. Confirmation mitigates accidental targeting; it is not a security sandbox. A local attacker with the user's permissions can interfere with CompControl and its targets.

Report concerns privately to the repository owner. Do not post credentials or private project paths/content in issues. Revoke exposed keys.
